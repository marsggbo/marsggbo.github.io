Kimi K3技术详解系列（二）：AttnRes 与 Stable LatentMoE

原文：Kimi K3: Open Frontier Intelligence

这是 Kimi K3 系列的第二篇。上一篇讲了序列维度上的 KDA：历史 token 怎么压缩、怎么遗忘、怎么在 GPU 上并行。本篇转到另外两个维度：层与层之间的信息怎么传，专家与专家之间的容量怎么扩展。

第一篇处理的是时间轴：一个 token 怎样访问很长的历史。本篇换两个坐标轴。深度轴问的是“第 80 层怎样直接利用更早层的表示”；宽度轴问的是“每个 token 要从 896 个专家里选 16 个时，怎样组织这些分支才具备可训练、可通信的成本”。MoE 是把 FFN 拆成多位专家、由 router 为每个 token 选择少数分支的结构；其中所有 token 都经过的分支叫 shared experts，按 router 选择的分支叫 routed experts。

图上半部分是宽度方向：full-width 的 shared experts 留住通用能力，routed experts 在较窄的 latent space（中间维度更小的计算空间）做特化。下半部分是深度方向：当前层从 embedding、已完成 block 和当前 block 的已有结果中选来源。后面的公式和模块都围绕这两条信息流展开。

1. 深度方向的默认残差有什么限制

标准 Transformer 每层通常做这样的事情：

\[h_l=h_{l-1}+F_l(h_{l-1})\]

$h_{l-1}$ 是上一层的 hidden state，$F_l$ 是第 $l$ 层的 attention 或 FFN 变换。这个结构并没有“丢掉”更早层的信息，残差会把它们一路带下来；限制在于，它们已经被压成一份统一的 $h_{l-1}$。第 $l$ 层不能显式决定“这次直接多取一点第 10 层的特征、少取一点第 60 层的特征”，只能接受前面层一路加工后的混合结果。

假设一个 90 层模型的第 80 层需要某个早期层提取的局部语法特征。这个特征只能混在第 10 层到第 79 层的连续变换里传过来，中间每一层都可能改变它。模型当然可以学着把信息藏在残差里，但这条通路不是显式的“回到第 10 层查一下”。

这和第一篇里的 recurrent state 很像：信息没有消失，却被压进一个不断更新的状态。Transformer 在时间方向用 attention 解决了“从历史 token 中选择”的问题；K3 的 AttnRes（Attention Residuals）把同一件事搬到深度方向，把“只接上一层”改成“从前面多个层级中检索”。

2. AttnRes：把残差连接改成深度上的 attention

以下先只看一个 token 位置。假设当前是第 $l$ 层，该位置在前面已经产生了 $l$ 个表示：

\[H_{<l}=[h_0,h_1,\ldots,h_{l-1}]\in\mathbb R^{l\times d}\]

其中 $h_0$ 是 token embedding，$d$ 是 hidden dimension。AttnRes 为当前层准备一个可学习的 pseudo query $\bm w_l\in\mathbb R^d$，把前面模块的输出当作 key/value。这个 query 对第 $l$ 层是固定可学习的，但每个 token 位置的 $H_{<l}$ 不同，所以最后的深度权重仍会随 token 内容变化：

# H_prev: [l, d]，前面 l 个层级的表示
# w_l: [d]，第 l 层自己的可学习 query
keys = rmsnorm(H_prev)                 # [l, d]
weights = softmax(w_l @ keys.T, dim=-1) # [l]
residual = weights @ H_prev             # [d]

公式写出来是：

\[\bm a_l=\operatorname{softmax}\left(\bm w_l\,\operatorname{RMSNorm}(H_{<l})^\top\right), \qquad r_l=\bm a_lH_{<l}\]

这里的 attention 没有发生在 token 之间，而是发生在层的深度轴上。它所回答的不是“这个词该看前文哪个词”，而是“当前 token 送入第 $l$ 个模块时，哪一个处理深度的表示更适合作为残差信息”。

为什么必须先做 RMSNorm？不同层的输出幅值可能差别很大。如果直接点积，某一层仅仅因为数值范数大，就可能在 softmax 中占据绝大多数权重；RMSNorm 把比较重点放回方向和内容，而不是谁的向量更长。

2.1 用 4 层的例子走一遍

假设前面有 embedding、layer 1、layer 2、layer 3 四个表示，当前 layer 4 的 pseudo query 计算出：

attention over depth = [0.05, 0.10, 0.70, 0.15]

那么 layer 4 使用的 residual 不是 h_3，而是：

\[r_4=0.05h_0+0.10h_1+0.70h_2+0.15h_3\]

这时第 4 层不必把所有深度信息都塞进上一层状态里再硬传下来；它能直接复用第 2 层的表征。换一个 token，前面各层输出变了，即便 pseudo query 不变，权重也可能移向 $h_3$。这比沿深度无差别累积多了一层选择能力。

3. 为什么 K3 使用 Block AttnRes

Full AttnRes 的算术量其实不算可怕，模型深度不到 100；真正贵的是，为了让后面层随时检索，每一层输出都不能立刻释放。若有 $L$ 层、hidden dimension 为 $d$，持久保存和跨 pipeline stage 传输的规模是 $O(Ld)$。这正好把“给深度更多选择”变成了一笔显存和通信账。

K3 的解法不是随手每 12 层取一个点，而是把层分成 block。已完成的 block 用块内输出的和压成一个 block representation；在当前 block 内，还保留“到上一层为止”的 partial sum。于是当前层既能看 embedding、以前各 block 的摘要，也不会偷看到同 block 后面尚未计算的层。以 93 层为例，8 个约 12 层的 block 加 embedding，共约 9 个长期保存的来源，而不是 93 个。

embedding  ───────────────┐
layers 1-12  -> block 1 ──┤
layers 13-24 -> block 2 ──┤──> 当前层的 depth attention
...                       │
当前 block 已过的层 -> partial sum ─┘

这个近似的直觉是：同一个 block 内相邻层的表示往往比较接近，没必要每一层都单独留一个长期入口；跨 block 的语义变化更大，值得保留独立入口。论文的消融显示，约 8 个 block 可以获得 Full 版本的大部分收益。

Block AttnRes 把“保留多个深度层级的可检索性”和“持久状态只保留约 9 份”放在同一个折中里。

上图把 K3 的三个方向放在一起：token mixing 对应 KDA/MLA，layer mixing 对应 AttnRes，channel mixing 对应 MoE。接下来进入宽度方向。

4. 896 个专家为什么要先进入 latent space

MoE 的目标是扩大“可选的计算分支数”：总参数可以很大，但单个 token 只激活少数专家。

K3 使用 896 个 routed expert，每个 token 选择 16 个，另有 2 个所有 token 都经过的 shared expert。问题在于，选择 16 个专家不代表只多算 16 次小函数：若每个 routed expert 都在 7168 维 hidden space 里做完整 FFN，权重容量、token dispatch 的通信量和专家 GEMM 都会按全宽放大。

K3 让 routed 分支先把输入从 7168 维压到 3584 维 latent space，在较窄的空间里完成专家计算，再投影回 7168 维。简化后的路径是：

x [7168]
  ├─> shared expert 1/2（保持全宽）
  └─> W_down: 7168 -> 3584
        └─> 选中的 16 个 routed experts
              └─> W_up: 3584 -> 7168
                     └─> 与 shared 分支相加

如果所有路径都必须先压到 3584 维，所有通用计算都会经过一个低维瓶颈；shared experts 保留 full-width 的公共通路，routed experts 则只在 latent space 提供稀疏特化。于是 896 个专家的成本落在窄空间，通用信息仍有不经压缩的路径。

5. 激活为什么会爆：先看 routed 分支的乘法链

一条 routed 分支要依次经过 down projection、专家内部的 GLU、16 个专家的加权聚合和 up projection，再与 shared 分支相加。这不是普通 FFN 里一次矩阵乘之后的小波动：前一段的异常幅值会成为后一段矩阵乘的输入，16 个分支的尺度差异又会在聚合时叠加。2.8T 规模和低精度训练下，这条乘法链比“某一层输出略大”危险得多。

K3 的第一道保险是在 routed experts 聚合之后、up projection 之前加 RMSNorm：

\[u=\sum_{i\in\mathrm{TopK}}p_iE_i(W_{down}x), \qquad y=W_{up}\operatorname{RMSNorm}(u)+y_{shared}\]

它不改变 token 选择哪个专家，也不把专家输出变成同一个方向；它只在进入最容易放大幅值的 $W_{up}$ 前，把 16 个专家聚合后的 scale 拉回可控范围。这里的 RMSNorm 是为 latent 路径带来的尺度波动配的一道闸门。

第二道保险是把 SwiGLU 换成 SiTU-GLU。SwiGLU 的两个分支在大输入上没有硬上限，低精度训练时更容易产生极端值。SiTU-GLU 给两个分支加 soft cap：

\[f(x)=\left[\beta_1\tanh(W_gx/\beta_1)\odot\sigma(W_gx)\right] \odot\left[\beta_2\tanh(W_ux/\beta_2)\right]\]

K3 取 $\beta_1=4$、$\beta_2=25$。在输入接近 0 时，tanh 近似线性，函数仍像 SwiGLU 一样工作；输入很大时，每个分支会平滑封顶，输出幅值上界约为 $\beta_1\beta_2=100$。

看图时重点看两段：原点附近红色 SiTU-GLU 跟 SwiGLU 接近，说明普通输入区域的表达能力没有被明显改写；大输入区域红线逐渐压平，说明低精度路径不会任由异常激活继续放大。

6. 896 个专家为什么会负载不均

即使激活稳定，router 还有另一个独立问题：它可能反复把 token 送到少数热门专家。假设一个 batch 有 8 个 token、4 个专家，每个 token 只选 1 个，朴素 Top-k 可能得到负载：

expert 1: 4 tokens
expert 2: 3 tokens
expert 3: 1 token
expert 4: 0 token

在专家并行（EP）中，专家 1 所在的 GPU 要处理 4 个 token，专家 4 所在的 GPU 没活干；整个 batch 的时间由最忙的 GPU 决定。专家越来越多时，少量偏差更容易把某些专家推成“过热”或“濒死”。

过去常见的 auxiliary loss 会在训练目标里惩罚不均衡；auxiliary-loss-free 路由则为每个专家维护一个 bias，热门专家减一点、冷门专家加一点。后者避免了额外损失，却要在“每步太小，调不过来”和“每步太大，来回震荡”之间调步长。K3 注意到，一次 router 前向其实已经给出了更直接的信息：每个 token 要让某个专家进入 Top-k，究竟还差多少分。

7. Quantile Balancing：从门槛直接反推 bias

令 $s_{i,j}$ 是 token $i$ 对专家 $j$ 的原始 router 分数。K3 用 bias 只调 Top-k 的选择，而不把 bias 混入最终专家权重；这样 bias 是调度旋钮，不会直接篡改已选专家之间的混合比例。对 token $i$，在当前带 bias 的分数中取第 $k+1$ 大值 $\alpha_i$。它就是“进入这个 token 的 Top-k 必须超过的 cutoff”。下一步若给专家 $j$ 候选 bias $b_j$，它能进入 Top-k，当且仅当：

\[s_{i,j}+b_j>\alpha_i\]

移项以后：

\[b_j>\alpha_i-s_{i,j}\]

换句话说，$s_{i,j}-\alpha_i$ 表示专家 $j$ 相对 token $i$ cutoff 的余量：正数已经够格，负数还差一点。若一个 batch 有 $m$ 个 token、$n$ 个专家、每个 token 选 $k$ 个，理想平均负载是 $q=mk/n$。我们不需要猜一个小步长，只需把 $b_j$ 设到恰好让 $q$ 个 token 跨过 cutoff 的位置，也就是余量分布的相应分位点。

# s: [m, n]，m 个 token 对 n 个专家的原始 router 分数
# alpha: [m]，当前带 bias 的 Top-(k+1) cutoff
headroom = s - alpha[:, None]
b_hat = -torch.quantile(headroom, q=1 - k / n, dim=0)
b = b_hat - b_hat.mean()

为什么最后要减均值？给所有专家 bias 同时加上同一个常数，不会改变 Top-k 排序；减掉均值只是去掉这个无意义的公共偏移。

以 8 token、4 expert、$k=1$ 为例，目标负载是 $q=8\times1/4=2$。Quantile Balancing 不是让 bias 每轮只移动一点，而是根据当前余量分布直接估计一个能让每个专家接近 2 个 token 的 bias；为避免同一 batch 用自己算出的 bias 重新路由，它在下一步才生效。

图中左侧是热门专家和“死亡专家”的负载差异，中间把每个专家离 cutoff 的余量排成一列，右侧用分位点推得的 bias 重新对齐。实际训练中，K3 不会把百万级余量全部 gather 到一张卡上，而是每张卡先统计每个专家的 1000-bin 直方图，再 all-reduce 整数计数，最后从合并直方图近似读取分位点。通信量从所有浮点余量降到每个专家固定数量的 bin，误差约为 bin 宽度级别。

8. 为什么 K3 的宽度设计要和稳定性绑在一起

把 routed experts 放进 0.5× latent space，并不是单纯为了少算一半矩阵。它同时降低了：

  • 896 个专家各自保存 FFN 权重的成本；
  • token dispatch 到专家后的 GEMM 规模；
  • 多专家聚合后传回全宽 hidden space 的压力。

但压缩宽度以后，shared expert、RMSNorm 和 SiTU-GLU 就变成了必要的稳定性配套；专家数量变多以后，Quantile Balancing 又承担了把计算量分回各个 rank 的职责。latent space、激活 soft cap、路由 bias 不是三个互不相关的小技巧，而是同一个“超大稀疏 FFN 如何可训练、可并行”的问题的不同答案。

论文的 scaling law 图报告 K3 相比 K2 约 2.5× 的 scaling efficiency 提升。这里的 scaling efficiency 是在相同训练损失/能力目标下所需计算量的拟合比较，不等同于单个 kernel 的 2.5× 加速；它还包含架构、训练配方和系统效率的共同影响。

9. 小结

本篇可以这样记：

  1. 标准残差只把上一层送给下一层，AttnRes 把“从前面哪些层取信息”变成了可学习的 depth attention；
  2. Full AttnRes 会保存所有层，Block AttnRes 用约 8 个 block 表示保留大部分效果；
  3. 896 个 routed experts 如果都在全宽空间运行，参数和通信太贵，因此先进入 0.5× latent space；
  4. shared expert 保住全宽通路，RMSNorm 和 SiTU-GLU 控制激活幅值；
  5. Quantile Balancing 从第 $k+1$ 个分数提供的门槛反推 bias，让负载均衡从“小步试错”变成“按 margin 分布直接估计”。
