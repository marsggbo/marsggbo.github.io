# Kimi K3 技术报告系列导读：从 KDA 到 1M context 的完整系统

> 原文：[Kimi K3: Open Frontier Intelligence](https://arxiv.org/abs/2607.24653)

---

Kimi K3 的技术报告内容很多：Hybrid Attention、KDA、Gated MLA、Attention Residuals、Stable LatentMoE、MoonEP、1M context 的 Agentic RL，还有一整套 serving 和 vLLM 适配。全部塞在一篇文章里，结果往往是每个名词都提到了，但没有一个真正讲透。

所以这次拆成一个三篇系列。顺序不是按报告目录机械切分，而是按“一个设计为什么会引出下一个设计”的依赖关系来读：

## 1. KDA：为什么线性 attention 需要重新设计成 GPU 能跑的样子

第一篇从 1M context 的 KV cache 开始，解释 KDA 如何把历史压缩成固定大小状态，为什么简单的逐 token 循环会拖垮 GPU，以及 chunkwise、lower-bounded decay 和 Gated MLA 如何一起解决效率与质量问题。

→ [第一篇：KDA 与 Hybrid Attention](https://marsggbo.github.io/blog/2026/20260902-kimi-k3-kda/)

## 2. AttnRes 与 Stable LatentMoE：深度和宽度方向怎么扩展

第二篇讨论两个结构变化。AttnRes 让每层不再只能接收上一层的残差，而是可以从前面多个层级检索；Stable LatentMoE 则解释 896 个 routed expert 选 16 个时，为什么要引入 latent space、RMSNorm、SiTU-GLU 和 Quantile Balancing。

→ [第二篇：AttnRes 与 Stable LatentMoE](https://marsggbo.github.io/blog/2026/20260902-kimi-k3-attnres-moe/)

## 3. 训练、Agent 和 Serving：新架构如何落到系统里

第三篇从 MoonEP、显存策略和 KDA context parallelism 讲到 1M context 的 Agentic RL，再看 prefix cache、speculative decoding、量化感知训练和 vLLM 的部署接口。重点是：换了模型结构以后，哪些“原本已经解决”的系统问题又需要重做。

→ [第三篇：训练、Agent 与 Serving Infra](https://marsggbo.github.io/blog/2026/20260902-kimi-k3-infra/)

三篇合起来，才是 Kimi K3 这份报告比较完整的技术图景：**序列方向减少无效历史读取，深度方向重新组织残差，宽度方向控制超大 MoE 的稳定性，系统方向则把这些状态和通信真正安排进 GPU 集群。**
